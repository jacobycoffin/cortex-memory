# Changelog

## Unreleased

- added the **pre-turn recall hook contract** (`preturn_contract.py`, #144): the hook that runs before a turn is the one place a slow or broken component can cost the owner his reply, so the promise is **checkable rather than documented** - `validate()` returns violations for a duplicate id, an id returned that is not in the store, **an id printed in the block but missing from the id list** (an unattributable memory), an over-budget block, **a missed deadline that is not reported as degraded**, an abstention that returns ids, and a degraded response that does not abstain. `degraded(reason)` is the required failure shape: **a hook may not fail the turn**. `deterministic()` proves the same request twice gives the same ids, because a hook that reshuffles cannot be cached and a cache that changes the answer is not a cache. **Live over all 4,718 recorded runs: 8 exceeded the token budget, 0 exceeded the limit, and 1,229 (26%) exceeded the 1,500 ms deadline** - so a quarter of pre-turn hooks are already over the deadline they are supposed to keep, which is the same story #224 told about latency arriving as a contract violation;
- added a **trust score per memory** (`trust_score.py`, #187): the store keeps the ingredients and never bakes them - a source-authority ceiling, a confidence, a currentness, edge evidence, confirmations, corrections, harmful reports, a retirement date - so a reader asking "how much should I trust this?" got eight columns and no answer. Four rules: **source authority is a ceiling, not a multiplier** (#41, `final = min(composite, ceiling)`); **an unknown part is excluded from the denominator, not counted as zero** (a memory never retrieved has *no* usage evidence, and scoring that as untrustworthy punishes every new memory); **penalties subtract, they do not multiply** (one harmful report dents a belief, it does not delete it); and **the score explains itself** (every contribution printed with its weight). **Live: 3,843 scored, median 0.50, p10 0.41, p90 0.585 - and the honest verdict is that it barely discriminates**: 3,423 of 3,843 sit in one 0.4-0.6 bucket and only **5 memories score above 0.8**, because confidence and currentness are near-constant across the store while evidence and use are near-zero for almost everything. The distribution now computes its own p10-p90 **spread** and says so when it is too narrow - a number that is nearly the same for everything is not a measurement (#147, #176);
- added an **audit digest** (`audit_digest.py`, #185): the store records a great deal and explains almost none of it (1,051 `lifecycle_events`, 1,791 `maintenance_log` rows, 19 `reconsolidation_events`), and there was no way to answer the only question a person asks - **what did this thing do to my memory this week, and was anything refused?** `audit_view` shows a table; this writes sentences. Rules: **every number names its window and its table**; **a quiet period is reported as silence** (a blank screen is indistinguishable from a broken query); **refusals are counted by class, never by content** (the digest must not become the leak the gate prevented); **what was *not* done is part of the audit**; and **an unreadable table says `unavailable`, never zero**. **Live, 30 days: 1,871 written - 1,834 DOCUMENT_EXTRACTED and only 37 OPERATOR_APPROVED (98% is import); 71 lifecycle changes (67 archived); 604 maintenance actions, all 604 dry runs; 0 corrections; 0 retired** - so the digest now says unprompted *"every maintenance action was a dry run (604 of 604): the maintenance path has been rehearsing, not acting"*;
- added a **consent gate at write** (`consent_gate.py`, #182): every other trust surface answers a question *after* the fact; consent is the one that must run **before the row exists**, because a memory that should never have been written cannot be un-written by a better explanation. Six rules: **default is `ask`, not `store`, for anything in a protected class** (a gate that defaults to writing only works when someone remembers to configure it); **a credential is refused** (#43); **work systems are refused outright, not asked about** (that boundary is his, stated once); **consent is per class** - authorising technical facts never authorises finance; **a refusal names the class and the rule, never the content**; and **the decision log holds the hash, not the text**, so "why is this in here" is answerable without a second copy. The gate **decides and logs; the caller owns the write** (a test asserts no memory is created). **Live over 400 sampled memories: technical 325, credential 47, finance 17, health 8, work systems 3 → 50 would be refused (12.5%), 25 asked about (6.25%)** - and the decision log is empty because **nothing writes through the gate yet**, so the store's existing contents were never gated. Honest limit: `classify()` is a **keyword screen that finds mentions**, so a note *about* rotating a token matches exactly as a leaked token does - the 47 is an upper bound on credential-shaped content, not 47 secrets;
- added **explain-a-memory** (`explain_memory.py`, #179): "why do you believe this?" has an answer spread across eight tables, and assembling it by hand is how a question gets answered with a plausible story instead of a record. This is the **memory-centric** view (`recall_explain` explains a recall, this explains a belief): identity with every value named by its column, provenance (`source_category`, `extraction_method`, session, quarantine), history (`supersedes_id`, `valid_to`), counters, edges **ranked by weight and matched on both sides**, and flags for retired/quarantined/stranded/unconfirmed/no-assertion content. **A missing field says `unknown`, not `0`** (#169's rule applied to a row) - a counter that was never written is not a count of zero. **Edges are matched `src_id = ? OR dst_id = ?`** because `add_edge()` stores pairs in canonical order, so the one-sided query silently reports a connected memory as isolated (a bug that has "proved" a no-op before). It also **states what it cannot say**: the store records the candidate set, not the model's reasoning, and it knows *when* a source was read, not *whether* it is still true. **Live on a real memory: preference, confidence 0.85, currentness 0.75, retrieved 80 / used 23, 40 edges (extends, supports, co_used), `source_ref unknown`**;
- added **correction memory** (`correction_memory.py`, #178): when he says *"no, the port is 8101"* three things must be true afterwards and the live store guaranteed none of them - **the old belief is retired not deleted** (`valid_to` set, content still readable, so "what did I think in October" has an answer), **the correction outranks everything later** (ceiling 0.97, and an `AGENT_INFERENCE`/`AGENT_PROPOSED`/`WEB_CLAIM`/`DOCUMENT_EXTRACTED` row **may not supersede a correction** - otherwise a later consolidation pass quietly re-derives the belief he just fixed), and **it is findable** (`standing()` is one query for "what have you been told to fix"). `record()` does write+link+retire in one transaction; **a correction without a target is refused** (it is just a new fact, and accepting it silently leaves two contradictory beliefs with no history); the chain is **depth-bounded and reports a cycle instead of hanging**. **Live: 0 memories carry `USER_CORRECTION`, 0 have `valid_to` set, and the 26 supersessions are all vault re-imports** - so every correction so far is indistinguishable from an ordinary fact and the store cannot tell "wrong" from "old";
- added **staleness prompts** (`staleness_prompts.py`, #177): a memory past its refresh window is not wrong, it is *unconfirmed* - so it is asked about, never demoted or rewritten: `Still true? "the backup runs at 3am" - noted 120 days ago, used 14 times (refresh window 90d).` Priority is **how far past the window × how often recalled**, so a 400-day memory nobody recalled is not worth his attention while a 100-day one in every conversation is; **pinned and correction memories are never prompted** (a standing instruction does not expire, and re-litigating a correction is how an assistant argues with its owner); the prompt is bounded at 160 chars; and a **45-day cooldown** backed by the module's own table stops the same question being asked twice. The refresh windows are **not redefined** - they come from `confidence_phrasing.STALE_AFTER_DAYS`, so "when does a fact go stale" has one answer. **Live: 1,049 stale of 3,843, 10 pinned skipped, and 895 of the 1,049 skipped as `no assertion`** - a memory needs ≥4 words of real content after scaffolding is stripped, because **"still true?" about a vault-note stub is noise, not a question** (#223's template-text problem arriving as a queue); what survives is real sentences, worst first;
- added **confidence phrasing discipline** (`confidence_phrasing.py`, #176): the sentence that carries a memory into conversation should not claim more than the memory can support. **Live: 817 of 2,000 memor(ies) contain an absolute word (40.8%)** - `every` 386, `never` 317, `must` 153, `exactly` 92, `none` 79 - and the phrasing ladder now derives its cut points from the store's own quantiles: `I'm not sure, but I have a note that` / `I think` / `I'm fairly sure` / `I know`, with a stale fact carrying its date (`as of 120 days ago`) instead of hiding it behind a hedge, and **unknown confidence phrased as unknown**, never as the average. Two limits are stated rather than papered over: **a quantile of a degenerate distribution is as much of a guess as a constant** - this store piles up at 0.78-0.80 so p25 and p75 came out **0.02 apart**, and `bands()` detects the collapse and falls back to the documented ceilings; and the overclaim audit is **a lexical screen that counts words and does not read sentences** (`every 30 minutes` is not an overclaim) which **reports and never rewrites**, because the stored content is the owner's text;
- added an **accessibility pass as a checker** (`accessibility.py`, #173) instead of a one-time review by eye: mechanical rules over a served page (missing `lang`, **a placeholder is not a name**, an unnamed button, an image without alt, a dialog without `aria-modal`, transitions without `prefers-reduced-motion`, no `:focus-visible` style, tabs without `aria-controls`), **computed WCAG contrast** against the declared palette with the threshold stated per text size, and a **`colour is not a signal`** rule for terminal output (a line that is only an ANSI hue carries no meaning when piped to a file). **`unknown` is not `pass`**: an unresolvable colour fails the check by being unmeasured, and the four things a machine cannot decide (focus order, what a screen reader announces, rendered contrast, touch accuracy) are **listed in every report** so a green result never implies more coverage than it has. `phone.html` fixed to pass: labelled search field, `aria-controls` on both tabs, `aria-live` on the results panel, explicit focus ring, reduced-motion block - **palette all AA, weakest pair 5.8:1 (`meta`), body 16.4:1**;
- added **render budget telemetry** (`render_budget.py`, #172): one view of every cap that reaches the prompt plus how much of each is actually used. **Live: budget p50 620 tokens, selection p50 542 (89%, p95 99%)** - the budget is saturated, and the render side is **never recorded** (`rendered_tokens` and `withheld_count` are 0 in every one of 4,724 runs), so "the budget was respected" is an assumption, not a measurement, and `report()` says `unmeasured`. Rules: a budget is reported **with its cap and its source**; **an unrecorded quantity is `None`, not zero** (`0` may mean nobody wrote it or nothing was rendered, and the two must not print the same); **the registry is the list** (`budgets()` names the constraints block 320 chars, bootstrap 900, memory budget 700 tokens, phone list 30 rows, voice summary 280 chars, answer receipt 120), so a new block cannot be added without a number a reader can check; and **estimate vs measurement is labelled** (`estimate_tokens` says so in its name);
- added a **share-safe export** (`share_export.py`, #171): sharing a memory should not require reading every line first, so the export does the work and is built out of **refusals** - a **credential is refused, not scrubbed** (#43), because what remains after redaction still says where the credential lives; machine paths and addresses are **genericised** (a path under the hermes home → `<home>/...`) so the sentence still reads; the **manifest names patterns, never values** ("3 password(s) redacted" is a receipt, and a receipt containing the secret leaks by describing itself); the file is **verifiable** (SHA-256 over the exact bytes, `verify()` recomputes it); and there is **no export-everything convenience** - explicit ids or an explicit filter, because that is the call made by accident. Inheritance: `sanitize_memory` already redacts secrets at write time, so export redaction protects **imported and legacy rows** - `dry_run()` reports counts only. **Live: 200 exported / 0 refused / 193 KB, paths 19, IPs 7, emails 1, passwords 3, checksum verified; dry run over 500 shows 46 paths, 12 IPs, 3 emails, 3 passwords**;
- added a **timeline view** (`timeline_view.py`, #170): how the store came to know what it knows - per-day/week/month series, a block-character sparkline, the busiest day, the **longest silence**, and per-kind totals for the window. Rules: **a gap is data** (an empty day is reported as 0, not omitted, because the quiet periods are the ones worth noticing), **counts come from a group-by** rather than from filtering a truncated page, and **the window is part of the answer** (`1,500 memories` means nothing without `in September`). Downsampling a sparkline takes the **maximum** per slot so a spike cannot vanish. **Live, 90 days: 2,810 memories at 31.2/day, busiest 2026-10-29 with 422, longest silence 13 days, 40 quiet days; by month 2026-07 737 · 08 342 · 09 1,740 · 10 898 · 11 126** - the lumpiness is the point: it separates a store that grew from one that was imported;
- added **latency reconciliation** (`latency_reconcile.py`, item 224): the store recorded `prepare_ms` p50 ≈ 1,209 ms while the latency work recorded p50 ≈ 141 ms on the same box - **both honest, describing different configurations, and nobody wrote down which**. The mechanism is the semantic stage: it calls `get_embedder()` and returns `{}` when the model is not importable, so a benchmark run in an environment without the runtime measures the lexical fallback (which also keeps the candidate pool small and makes `select` cheap). `availability()`, `stage_profile()` and `describe()` now put the flag beside every number; **live: p50 1,209 / p95 5,976 over 500 runs, heaviest stage `select` 281 ms then `semantic` 264 ms, production 8.6× the benchmark**, and this interpreter reports the semantic path unavailable - which is exactly how the 141 ms figure was produced. Rule: a latency number is not a fact until it says which configuration it measured;
- added a **health screen** (`health.py`, #169): one read that answers *is anything wrong* - latency percentiles, storage and growth, abstention share, turns that retrieved nothing, consolidation queue, template text in content, and how much is pinned - each with its **source, window and threshold printed**, `unknown` when a source cannot be measured (never `0`), and **the worst check deciding the verdict** so a green average cannot hide a failing tail. **The first live run returns FAIL and is right to**: latency p50 **1,209 ms** / p95 **5,976 ms** with **494 of 500 runs over the 150 ms target**, storage 800.8 MB at ≈6.1 MB/day, and **79.0% of active content still carrying the vault template**; abstention 0.8%, turns without retrieval 0.8%, pinned 14. `prepare_ms` may include prefetch waiting, so the latency discrepancy with the 142 ms figure is filed as its own item rather than smoothed over;
- added a **path finder** (`path_finder.py`, #165): the one question a graph answers that a list cannot - how are these two memories connected - as a **breadth-first shortest path** with deterministic neighbour order, `MAX_HOPS` and a visited cap, the **weakest link** named, and routes through a hub flagged as mostly about the hub. Running out of hops reports *no path within N hops*, explicitly **not** "unrelated". **The live measurement is the interesting part: of 20 random active-memory pairs only 7 (35%) are connected within 6 hops, the median path is 5 hops, and 2 of those 7 depend on a link under 0.1** - so the graph answers this question for a third of pairs and, when it does, the chain is long and weak. - added **saved views** (`saved_views.py`, `cortex-memory views …`, #163): a saved view is **a named filter, never a script** - the spec may name a kind, project, state, search term, sort and limit, and nothing else. **Unknown fields are refused** (a typo that disappears produces a view that is quietly wrong), values containing SQL fragments are refused, sorts and states are an allowlist, and `explain()` returns the parameterised clause plus its match count so a view can be checked before it is trusted. Use is counted (`use_count`, `last_used_at`) and `unused_views()` leads with the ones worth deleting; `install_presets()` adds new/pinned/unsure/cold once and **never overwrites a view somebody tuned**. **Live on a copy: new 3,843 · pinned 14 · cold 11 · unsure 3,843 (a sort, not a filter — worth knowing); top project views homelab 62, Jarvis voice agent 19, cortex-memory 14**;
- added a **precomputed graph layout** (`layout_cache.py`, #162): a force simulation runs on the client, takes seconds, gives a different picture each time and costs battery on the device least able to spare it - so positions are computed **once, deterministically, on the server**: connected components by union-find (root = smallest id, so edge order cannot change the result), components in a deterministic grid largest-first, and nodes on concentric rings by degree inside each. **Isolated memories get no position** (a memory with no edges has nothing to be near, and a dot for it would mean nothing), the cache **states its age** and reports `stale`, and `neighbours()` serves the handful of points a drill-down actually needs. **Live: 6,203 nodes across 270 components in 112ms**; the full payload is 553 KB so nothing should ship it whole, while a neighbour query is **8 points / 599 bytes**. A position is a convenience, not a claim about meaning;

An ambiguous header - one where the section runs into the body - is **left alone**, because guessing where a heading ends mangles a note. The original is kept verbatim in `vault_headers` so `restore()` undoes any row, nothing is ever blanked (an empty body falls back to the title), and a dry run is the default. **Live, on a copy: 3,016 of 3,817 active memories carry the header; 1,500 are delimited and rewritable, saving 422,532 characters, 1,516 are ambiguous and untouched, and a second run rewrites 0**;
