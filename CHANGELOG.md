# Changelog

## Unreleased

- added **contradiction clustering** (`contradiction_cluster.py`, `scripts/contradiction_cluster.py`, a `contradictions` tool action, #52): disputes are collapsed with a union-find into **one review item per connected component**, with a topic from the shared subject/predicate (or the words the members share), the strongest member named as a recommendation, and `resolve()` resolving **every pair in the item at once** with the actor recorded - never auto-resolving. A bridge (`candidates`/`record_conflicts`) exposes the conflicts the two existing detectors see, **reporting by default and filing only with `apply=True`**. Live finding: the `disputes` table is **empty** (nothing in the write path records one), the triple check finds **0** conflicts, and near-miss at a wide scan yields 40 proposals that spot-check as duplicated vault notes ('18:48' vs '21:03'), not contradictions - so a pure timestamp/filename difference is now filtered as trivial and filing stays off;
- added a **belief provenance chain** (`provenance.py`, `scripts/provenance.py`, a `provenance` tool action, wired into corrections and merges, #51): for any fact, the ordered sequence of evidence that produced it - origin from its own row (captured / verified / corrected, with source type, category and extractor), plus corrections, merges, disputes, supersessions and independent evidence from the tables that already hold them, and `link()` for events with nowhere else to live. The chain is **assembled, never authored**: a step with no evidence is not invented, and a fact the store cannot explain says `unknown origin`. Live over 400 active memories: **357 have two steps, 40 three, 2 four or five, and exactly 1 is origin-only (0.2%)** - the store already knows why almost every fact exists, it just never showed it in one place;
- added **entity nodes** (`entity_nodes.py`, `scripts/entity_nodes.py`, #49): every known entity gets a record with a kind, canonical name, summary and timestamps, and `page()` assembles aliases, facts, first/last seen and shared-memory neighbours **from the tables that already own them**, so a page cannot drift. The kind is a guess that says so - a small lexicon plus name shape (host-shaped → device, email → account, street address → place), everything unclear stays `unknown`, and a person can override with `set_kind`. Live: **1,960 entities** got nodes, of which **1,931 (98.5%) are `unknown`** - the store's entity names are mostly headings, ids and one-off names, which is exactly why kind must be conservative; the useful page is aliases + facts + neighbours, and CT112 assembled 5 facts and 4 neighbours with a first-seen date;
- de-flaked the selection snapshot test (#220): the assertion compared selected **contents in order** against a fixed list, which can only hold while no two selected memories score exactly equal - when they do, `rank_by_score` breaks the tie on memory id, and ids are UUIDs generated per store, so the order changes between runs. It now asserts **membership** (a Counter) plus the recorded reasons, with a new test pinning the invariant that ranking does not depend on input order and one showing a deliberately tied pair always returns both memories. **No root cause was reproduced**: 10 hash seeds, repeated runs and six fresh stores with a seeded tie all passed, so the change removes the only known order-dependence in that assertion rather than a confirmed trigger;
- added an **extraction prompt regression suite** (`extraction_regression.py`, `tests/fixtures/extraction_cases.jsonl`, `scripts/extraction_regression.py`, #47): 10 synthetic conversations with the facts they must and must not yield, matched on tokens rather than wording, including three **declared gaps** (a negative preference, a multi-step procedure, two facts in one flat sentence) that are not extracted today and will show up as appeared facts if a future reader catches them. A **baseline** records what each case produced so a model swap diffs as appeared / vanished facts rather than a silent change;
- added **backfill on schema change** (`backfill.py`, `scripts/backfill.py`, #45): a registry of derivations (scope, entities, importance, volatility) with a **plan** that changes nothing, a **run** that records each pass in `backfill_runs`, and a **verify** whose clean result is the condition for bumping the recorded schema version. A field that cannot be re-derived from the stored row is declared **`not_derivable`** rather than approximated (extractor confidence). Idempotence needed a sentinel: "the field is missing" and "the field is not applicable" are the same predicate, so rows with nothing to fill are **marked** and never rescanned. Live: 3,320 rows lack scope and 987 lack entities; a 300-row pass scanned 600 and filled 117; with the alias table seeded, the entity derivation filled **111 of 300**;
- added **entity resolution at write** (`entity_resolve.py`, `scripts/entity_resolve.py`, wired into the capture path, #38): mentions (host-shaped tokens, `the <qualifier> box` descriptors, proper nouns) are resolved against the alias table **before the row is stored**, a descriptor resolving through its qualifier and never through "box", a hostname through its first label, and an **ambiguous name left unresolved** rather than merged into a stranger. `aliases.from_memories` now refuses values that are not names (vault paths, dates, `›` headings): seeding 2,000 memories dropped 531 junk aliases (2,513 → 1,982 rows, 811 → 383 entities). Live: with the table empty **0 of 8,456 mentions resolved**; seeded from the store's own entities, **1,247 of 8,456 (14.8%)** resolve, 26 ambiguous, 7,183 unknown;
- added **self-correction detection** (`self_correction.py`, `scripts/self_correction.py`, a `correction` tool action, wired into the capture path, #33): a strong marker ("I meant", "correction:", "scratch that", "that's wrong", "not X, but Y", a message opening with "No,") **supersedes immediately** instead of queueing behind the judge, writing the new fact as `USER_CORRECTION` with `supersedes_id` on the winner and the loser kept as `superseded`; `undo()` restores the pair. The **weak** path (a bare "actually") ships **off** (`CORTEX_WEAK_CORRECTION`): on the live store it produced 2 hits in 238 user-typed memories and **both were false positives**;
- added **scope capture** (`scope_capture.py`, `scripts/scope_capture.py`, wired into the capture path, #30): every write records **who / where / when** from its own sentence - a small named lexicon for people, hosts and projects for where, dates and relative markers for when - **filling only what is missing**, so an explicit caller scope always wins. A fact with none of the three is marked `global` and counted: live, the first 5,000 sampled memories were **100% global**, and backfilling 500 scoped **261 of 500 (52%)** (who 166, where 98, when 114), moving the share to 94.8%;
- added **merge with diff, consent and undo** (`merge_review.py`, `scripts/merge_review.py`, a `merge` tool action, #29): a merge is shown **side by side** with a word-level diff, `apply()` refuses without `consent=True` **and a named consenter**, and the old record is retained - the source keeps its content and moves to `superseded`, both prior texts are stored in `memory_merges`, and `undo()` restores the pair exactly. Without consent the tool action is a preview;
- added **write-time dedup** (`write_dedup.py`, `scripts/write_dedup.py`, and a `dedupe_check` tool action, #28): the insert / merge / reject decision is made against the **nearest memories before the row exists**, using the thresholds this store already uses elsewhere - verbatim at 0.85 Jaccard, restatement at 0.60 similarity with 0.80 containment of the shorter text. Live survey of 120 recent memories: **1 verbatim duplicate (0.8%)**, 119 genuinely new;
- added **two-pass extraction** (`two_pass.py`, `scripts/two_pass.py`, a `disagreements` tool action, #27): a cheap pass proposes candidate facts and a strong pass accepts each one; **disagreements become review candidates** in an `extraction_disagreements` queue - `over_reach` (cheap proposed, strong refused - its usual failure) and `miss` (the cheap pass missed something the strong reader saw). A failing gate is a refusal, never an acceptance. Ships off (`CORTEX_TWO_PASS=1`) because it changes what gets written; the queue is the point, not the agreements;
- added **one-command undo of a learned change** (`undo_learned.py`, `scripts/undo_learned.py`, an `undo` tool action, wired into semantic consolidation, #213): each run becomes **one reversible step** - `begin()` snapshots the rows the run may move (`state`, `content`, `confidence` for the ids it selected), `commit()` records what actually changed, and `undo()` puts those rows back and nothing else. Narrow on purpose: a wider snapshot would be a database rollback with a friendlier name. The run id is reported as `undo_run_id` with `undoable_changes`;
- added the **before/after demonstration** (`lesson_demo.py`, `scripts/lesson_demo.py`, #211): a change is shown as the **question it changes** - re-run a recorded query against a `--baseline` copy of the store and diff the selections. With a baseline the difference isolates the change; without one the run is labelled **drift, not a demonstration**, because the recorded selection came from a differently configured retriever and months of new memories, and a tool that reports drift as causation is the thing this item exists to stop. Live: one near-miss pair recorded between two selected memories changed **1 of 5** questions, with the other four unchanged as the control;
- added **machine-edge provenance** (`edge_provenance.py`, `scripts/edge_provenance.py`, and the `why` sentence now says it, #206): every edge's evidence is classified `human` / `document` / `machine`, and only the first two are **citable** - `citable()` is the gate. A machine edge was produced *by recall* (two memories retrieved together are linked because the retriever retrieved them), so it may guide retrieval but is never quoted as a relationship someone stated; `mixed` is judged by its **strongest** witness, because being told once outranks a thousand co-occurrences. Live: of 14,923 evidence rows, **70.6% are machine**, 29.4% document, **0% human**;
- added **session dedupe for associations** (`session_dedupe.py`, `scripts/session_dedupe.py`, wired into `co_retrieval.materialize`, #204): a pair is admitted only with **two distinct sessions** behind it, checked at the materialise door so any future writer that counts turns instead of sessions is refused there too (`single_session_refused`). `audit()` reports which recorded pairs rest on one session, and `weight_cap_for()` gives **zero below the bar and the full cap at it** - the second session is what distinguishes evidence from repetition. Live: `co_retrieval_observations` is empty, and the associations that do exist came from `auto_judge` (4,136 supports, 2,417 extends) and `explicit_wikilink` (3,573), not from co-retrieval;
- added **boost caps** (`boost_caps.py`, `scripts/boost_caps.py`, enforced in retrieval, #203): a ceiling on the **sum** of history boosts, not just on each one - usage 0.09, entity 0.15, session 0.10, association 0.10, total **0.25**. A relevant memory with history keeps its boost; the cap binds only when a third family stacks (usage + entity = 0.24 passes; adding session = 0.34 is trimmed by 0.09), which is exactly the memory winning on popularity alone. The excess is removed from the score with `boost_capped` / `boost_total` left on the result, so ranking stays explainable;
- added **plain-English edge explanations** (`edge_explain.py`, `scripts/edge_explain.py`, and a `why` tool action, #85): every relation renders as a sentence a person can argue with - *\"A → B because retrieved together 3×; one note links to the other — strongly supports.\"* - built from the evidence **types** actually recorded (each with its own phrase and count), the strength in words rather than decimals, and the link's **status**: quarantined (#84), vetoed (#79) or a near-miss (#80) all say so in the same sentence, because \"why are these connected\" and \"why did this not surface\" are the same question from different sides;
- added **association quarantine** (`edge_quarantine.py`, `scripts/edge_quarantine.py`, wired into retrieval's graph expansion, #84): an edge created after an explicit **adoption epoch** is recorded but **non-scoring until it has two independent witnesses** (distinct evidence *types* - two rows of one type are one witness, and `add_edge`'s own `legacy_unattributed` row explicitly does not count). Edges older than the epoch are **grandfathered**, which is the measurement: only **415 of 13,970 live edges** carry two distinct evidence types, so applying the bar retroactively would silence 97% of the graph in one commit. Nothing is quarantined until an epoch is adopted, so the change is inert today;
- added **serial-position weighting** (`serial_position.py`, `scripts/serial_position.py`, wired into selection behind `CORTEX_SERIAL_POSITION`, #82): measured from the access log, memory selected in the **last session quartile is used more** (0.281) than in the middle two (0.243 / 0.223) - about +0.04 absolute, +17% relative - while the *first* quartile is mid-pack, so there is **no primacy bonus to hand out**. Late in a session the working set gets x1.08 and a stale in-session memory x0.96; counters `serial_position_boosted_count` / `_penalised_count`. Ships **off**: the frozen set has no session history so it cannot decide this, and an access-log measurement is enough to build the weight, not to change every recall;
- added **near-miss suppression** (`near_miss.py`, `scripts/near_miss.py`, and a `near_miss` tool action, #80): pairs that are similar on purpose and wrong together (\"port 8100\" vs \"port 8100 in staging\") are recorded as a **negative association**; when both would be selected, the weaker half is dropped and the reason reported (`near_miss_dropped_count`). Detectors only **propose** - a recorded pair is the only thing that suppresses - and the read path creates no schema and commits nothing, so enabling it is inert until somebody judges a pair confusable. Detection: 2,000 most recent memories -> 67 proposals in 134s (a nightly job, not a recall path);
- added **association feedback** (`assoc_feedback.py`, `scripts/assoc_feedback.py`, and a `related` tool action, #79): "those two are related" creates the edge (or reinforces it, capped at 1.0, with `user_feedback` evidence); "those two aren't related" is a **veto, not a weight of zero** - the edge drops to 0.02 and the pair is recorded so `co_retrieval` reports it as `vetoed` and never re-proposes it. Neither direction deletes an edge or its evidence, and a whole sentence can be applied when both ends resolve;
- added **cross-project bridges** (`cross_project.py`, `scripts/cross_project.py`, and a `bridges` tool action, #78): a memory from **another** project is surfaced only when the match is strong - containment on the shorter side floored by a 3-token absolute overlap, bar 0.60 - capped at **2 per query** and **always labelled** with its project (or `unscoped`). Bridges are never counted as hits for the active project. Ships **off** (`CORTEX_CROSS_PROJECT=1`): live, only **242 of 8,369 memories (2.9%)** carry a project at all, so nearly every bridge is an unscoped vault note;
- added the **path query** (`path_query.py`, `scripts/path_query.py`, and a `path` tool action, #75): *"how are these two related?"* returns the **hops with their evidence** - relation, current weight and the `edge_evidence` summaries behind each hop - traversed **undirected** (a relation can be directional; the question is not) and capped at depth 4 with a 20,000-node frontier. When no path exists the reply lists **shared neighbours and shared entities** instead of nothing, and a hop with no evidence row says so. Live: the graph is **270 components** - one giant of 5,362 and 238 islands under 5 nodes - so "no path" is often the true answer;
- added **degree caps** (`degree_caps.py`, `scripts/degree_caps.py`, #73): no memory may hold more than **24** edges (`CORTEX_MAX_DEGREE`); past the cap the edge is recorded as **overflow grouped by hub and relation** rather than dropped or silently refused, so a topic node (#74) can adopt the group wholesale. Wired into `co_retrieval.materialize` - the bulk creator of edges - so hubs cannot be manufactured by a bulk pass; live: **121 memories over the cap**, worst 165 edges, and every one is a vault-import note rather than a user fact;
- added **reversible edge decay** (`edge_decay.py`, `scripts/edge_decay.py`, #72): an edge unreinforced for N days loses weight on a **120-day half-life** floored at **25% of its base**, keys on `last_reinforced_at` rather than creation, and **records the base weight first** so `restore()` puts it back exactly. `edge_evidence` rows are never touched - a stale link is evidence that nobody asked, not that the memories are unrelated. Live: 13,970 edges, all beyond a half-life, 14,923 evidence rows kept; the steepest are 0.04 `co_observed` links fading to 0.02;
- added the **derived-metadata guard** (`derived_metadata.py`, `scripts/derived_metadata.py`, #69): the split between what may be regenerated (features, keywords, tags, tokens, normalised text, FTS rows) and what may never move (content, confidence, kind, source, timestamps, supersedes_id, entities) is now explicit in code. `regenerate()` rebuilds derived rows and **verifies the content fingerprint is unchanged before reporting success**; `assert_immutable()` turns the check into a library call for consolidation/import/replay paths; the restore ladder re-indexes through the guard, so a restore cannot rewrite what the user said;
- added **fact expiry classes** (`expiry_classes.py`, `scripts/expiry_classes.py`, and a `reviews` tool action, #64): every fact is assigned **permanent / review-in-90d / review-in-30d** at write, derived from its volatility class (#31) and kind (#87) rather than from a blanket rule, and baked into the record. A due record is a **question, not a sentence** - `acknowledge()` pushes the date out because somebody confirmed it, and nothing is deleted; live backfill on a copy: 3,828 assigned = 479 permanent, 3,032 review_90, 317 review_30;
- added **constraint memories** (`constraints.py`, `scripts/constraints.py`, and a `constraints` tool action, #60): budgets, allergies, hard nos and limits are promoted at write and rendered as an **always-on context block** in every turn, because similarity search is precisely the mechanism that would miss them (a shellfish allergy scores zero against "recommend a restaurant"). Detection leans inclusive, a hard preference from #59 counts even when no keyword fires, the block is capped and importance-ordered, and it never raises into a turn;
- added **preference strength** (`preference_strength.py`, `scripts/preference_strength.py`, and a `preferences` tool action, #59): every preference is **hard** (do not deviate; say so if it cannot be met), **firm** (deviate only with a stated reason) or **soft** (deviate freely, mention it). A hard marker beats a soft one in the same sentence because over-obeying costs a question and under-obeying costs an accident; a hedge placed before the verb softens it ("mildly prefers" is soft, "prefers X, usually" stays firm); an unmarked preference is firm, since silence about intensity is not evidence of weakness. `hard_rules()` lists what a plan may not violate;
- added **negative facts** (`negative_facts.py`, `scripts/negative_facts.py`, and a `negation` tool action, #58): "X is not true" is a recorded opinion with a date and a source rather than an absence, so `answer()` can return affirmative / negative / **both** (a dispute, #48, never a coin flip) / unknown. Polarity is derived once at write and stored; a negative never deletes its positive; nothing infers a negative from a missing positive. Classification is gated to **statement-shaped** text - without that gate the live count read 53.6% negative, almost all of it imported vault chunks that merely contain the word "not"; with it the store holds 148 negatives (1.8%), 644 affirmatives and 7,577 unclassified passages;
- extended decay to **follow volatility** (`decay.py`, `retrieval.py`, #54): half-life now comes from the memory's class (ephemeral 7d, seasonal 60d, **durable 540d so a stable fact plateaus** at ~90% after a year) instead of one curve for everything, and the retriever attaches the class with one cached lookup per memory. **Measured on the frozen set before shipping: hit@6 0.6250 off vs 0.6208 on** (recall 0.2944 vs 0.2931, MRR 0.4417 vs 0.4401), so `CORTEX_DECAY` stays unset and default scoring is unchanged;
- added **entity timelines** (`entity_timeline.py`, `scripts/entity_timeline.py`, and a `timeline` tool action, #50): every memory attached to an entity (or any of its learned aliases) in the order the store learned it, with **change markers**: a supersession pair reads as "replaced by ..." / "replaces ...", while two facts that merely disagree stay unmarked because a dispute is not a change (#48). Undated rows sort last rather than at the epoch, suppressed rows appear with their state, and `--changes` lists only the was/now pairs;
- added the **write-path dry run** (`dry_run.py`, `scripts/dry_run.py`, and a new `dry_run` tool action, #46): "what would you remember from this?" runs split -> anchor -> extract -> refuse/redact -> dedupe -> score -> throttle -> learned-rule with **no writes at all**, and reports per candidate whether it would be remembered, a duplicate, refused, redacted, covered by a learned rejection, throttled, or dropped below the extraction bar. Purity is tested (no memories, no proposals, no throttle advance, no refusal counter), and the action is advertised in the tool schema so it can be asked in chat;
- added **redaction receipts** (`redaction_receipt.py`, `scripts/redaction_receipt.py`, #44) plus `SanitizedMemory.redactions` labels: a redaction is no longer silent - the receipt names the pattern ("redacted 1 credential (api key)"), never the value, and appears in the `remember` response and in the turn-level write receipt (#37) in the same breath as "remembered 2 things". Receipts attach to the proposal (audit must not start at promotion), are idempotent, are stripped of anything token-shaped as a second line of defence, and are scrubbed with their subject;
- added **secret refusal** (`secret_refusal.py`, `scripts/secret_refusal.py`, #43): a credential is **refused**, not scrubbed - a row reading `password = [REDACTED]` claims the store knows the value, which is worse than saying nothing. Private keys, provider tokens and labelled credentials **with a value** are refused and counted; placeholder values (`***`) are redacted; a mention or a location ("the password is stored in the vault") is allowed. Wired at both boundaries - the `remember` tool returns `refused: true` writing nothing, and capture refuses only the offending candidate so one pasted key does not cost the user their other facts;
- added **quote retention** (`quotes.py`, `scripts/quotes.py`, #42): the verbatim sentence a candidate came from is kept beside the proposal (and follows it into the memory on promotion via `adopt()`), so a wrong fact can be traced to what was actually said. Quotes are never recalled, scored or injected; `verify()` measures drift between the stored fact and its quote (numbers count - a drift check that drops every digit cannot tell port 8100 from 8200), and `drifted()` is the audit shortlist;
- added **source weighting as a confidence ceiling** (`source_weight.py`, `scripts/source_weight.py`, #41), wired into the agent proposal path: `effective = min(stated, authority(source))` - a web claim cannot store 0.95 confidence, an unvetted agent proposal cannot store 0.88 (it is capped at 0.50), and a diffident user statement is never inflated. Retrieval already weighted sources for ranking; this binds the same ordering to the confidence stored with the memory. `--over` measures the backlog: 4,178 of 8,369 live memories (49.9%) carry confidence above what their source can support;
- added **temporal anchoring at write** (`anchoring.py`, `scripts/anchoring.py`, #40), wired into extraction: "yesterday", "last Tuesday", "3 days ago", "in 5 days", "last month" and "October 3" gain an absolute date in parentheses (`last Tuesday (2026-11-17)`), while the phrase itself is kept - rewriting it to a bare date would lose how the user said it. Idempotent, only resolves unambiguous phrases, never invents a time of day, and leaves an impossible date like "February 30" alone;
- added an **entity alias table** (`aliases.py`, `scripts/aliases.py`, #39): per-entity names learned from usage with hit counts, folded keys (case, leading article, spacing, surrounding punctuation - nothing more), `resolve()`/`expand()` for retrieval, and full editability (`remove`, `merge`) because an alias table nobody can correct becomes a source of confident wrong answers. `from_memories()` teaches the names the store already uses; aliases longer than 48 characters are refused because imported document headings are not entities;
- added **write receipts in chat** (`write_receipts.py`, `scripts/write_receipts.py`, #37): a turn that writes memories ends with one capped line naming them and a short id for each ("remembered 2 things - 1) ... (a1b2c3) 2) ... (d4e5f6) - say fix <id> <words> or forget <id>"). The ids close the loop: `apply_edits()` interprets `fix`/`forget` in the next message - `forget` **suppresses** (content and audit kept) rather than deleting, `fix` writes a USER_CORRECTION that supersedes the wrong version. Harness turns collect their own writes so `turn.receipt()` costs nothing extra; silence when a turn wrote nothing;
- added **automatic write throttling** (`write_throttle.py`, `scripts/write_throttle.py`, #36): automatic memory writes are capped per turn (5), per hour (25) and per session (40), all three overridable. A throttled write is **deferred, never dropped** - the proposal stays staged so a later turn can take it - and user-stated material is exempt, because the user asking is the strongest evidence the store will ever get. Wired into the auto-judge's write path;
- added **reject-then-learn** (`reject_learn.py`, `scripts/reject_learn.py`, #35): a rejection is recorded as a named rule (reason code + keyword signature) and a later proposal matching it at Jaccard >= 0.60 is dismissed without a model call - and dismissed **in the store too**, so the backlog still drains instead of stalling behind permanently-pending proposals. Only rejections are learned (a rule that could auto-accept is #26's failure again), a rule never matches `USER_*` material, and `forget_rule()` exists because a rule that misfires must be removable;
- added **multi-fact splitting** (`splitting.py`, `scripts/splitting.py`, #34) and wired it into extraction: a compound sentence carrying two independent facts now becomes two records, while a comma list stays one. The rule is not "split on punctuation" but "split only where each side survives alone" - three words, a verb, no continuation clause, and never inside a URL, path, code span, parentheses or quote;
- replaced the flat/magic importance with a **rubric** (`importance_rubric.py`, `scripts/importance_rubric.py`, #32): a kind anchor (identity 0.95 > commitment/decision 0.88 > correction 0.86 > preference 0.82 > prospective 0.80 > procedure 0.75 > semantic 0.66 > tool 0.60 > episode 0.40) plus bounded modifiers (user-stated, corroboration, a credential/port/path, ephemeral, hedged, fragment) inside a +/-0.16 band, so it stays a rubric instead of becoming a second classifier. The capture path's hardcoded `0.78` is gone;
- added **volatility at write** (`volatility.py`, `scripts/volatility.py`, #31): every memory is classified **durable / seasonal / ephemeral** from evidence in its text first and its kind second, stored in `memory_volatility`, and used by the forget ladder as a window multiplier (ephemeral x0.5, seasonal x0.75, durable x1.5). A durable marker outranks an ephemeral one because losing a stable fact costs more than keeping a stale one, and durable kinds are never shortened by a stray marker;
- added **gated co-retrieval edges** (`co_retrieval.py`, `scripts/co_retrieval.py`, #67): pairs are *observed* whenever both memories are in one turn's retrieved set, but an edge is created only after **3 independent sessions** agree (three retrievals inside one session count once), with weight `min(0.45, 0.15*log1p(sessions))` decayed on a 90-day half-life - so the tenth session adds little and a pair nobody re-confirms fades to zero and stops qualifying. Observations live in their own table so an unearned pair costs three rows and no edge;
- added an **immutable recall event log** (`recall_events.py`, `scripts/recall_events.py`, #66): one append-only row per recalled memory per turn carrying rank, score, numeric score components and retriever, plus a separate `citation` event so `used_in` (cited in the answer vs merely injected) is **derived rather than mutated** - both facts survive instead of one overwriting the other. Immutability is enforced by SQLite triggers (UPDATE/DELETE abort), the query is never written into a memory, and `query_leaked_into_memory()` exists to prove it;
- added a **strong-model gate** on automatic memory writes (`model_gate.py`, #26): in the auto-review path a cheap model's `remember`/`evidence_only` becomes a **deferral** - the proposal stays staged for a human and the report records why - while its `reject`/`defer` still passes through, because refusing is always safe. Cheap families are a prefix deny-list (`CORTEX_WEAK_MODELS`), strong families an allow-list used in strict mode (`CORTEX_STRONG_MODELS`, `CORTEX_STRONG_MODELS_STRICT`); the shipped auto-judge default model is `openai/gpt-4o-mini`, which is exactly the case this is for;
- added a **disputed** validity state alongside current and superseded (`dispute.py`, `scripts/dispute.py`, #48): two sources that disagree are recorded as a named pair, neither side is demoted (a dispute is not evidence that one is wrong), and recall can hedge - `hedge()` says how many recalled memories are disputed rather than picking a winner. `resolve(winner=...)` turns a dispute into an ordinary supersession, which *is* a claim about truth and has to be made deliberately; retrieval reports `disputed` as a component without scoring it;
- made retrieval ranking a pure function (`rank_by_score`) so ties break on memory id rather than dict order, and gave `forget_preview.envelopes()` an `at` parameter. Two clock/ordering defects found by the suite itself: the envelope audit trail decided "expired" from the wall clock, so its test passed in the morning and failed after lunch; and ranking ties depended on insertion order;
