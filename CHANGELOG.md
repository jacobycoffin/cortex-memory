# Changelog

## Unreleased

- added a **regret guard** (`regret.py`, #90): a memory that was walked down the ladder and came back (restored, or used again) widens its kind's windows by 0.25 per revival within 180 days, capped at 3x, never shrinking below the declared policy. Regret only ever delays forgetting - the failure is asymmetric, and keeping something a cycle longer costs nothing. Live on a copy: 35 semantic revivals in the window hit the cap, dropping planned `active->cold` moves from 100 to 55 per sweep. Reported in `policy()`, `explain()` and the CLI;
- added **preview-then-apply semantic forgetting** (`forget_preview.py`, `scripts/forget_preview.py`): a query produces matches plus an **envelope** naming exactly those ids; an apply is only accepted if every id was previewed and the envelope has not expired (30 min, `CORTEX_FORGET_PREVIEW_MINUTES`), so no code path forgets "whatever the query returned" by the time a human has read the list. Protected memories are refused unless `--force`; a partial mismatch refuses the whole batch; every envelope and apply is recorded and `--history` lists them; forgotten memories remain restorable;
- named every **never-prune protection** and made them auditable (#88): `pinned`, `open_commitment`, `useful_feedback` (`usage_records.outcome` helpful/validated), `use_evidence` (90d), `edge_bearing` (edges with `evidence_count >= 2`, override via `CORTEX_FORGET_EDGE_EVIDENCE`) and `core_member`. `protection_policy()` documents each; `forget_ladder.py --why <id>` explains one memory's verdict; a protection query that errors is now **reported** instead of swallowed, and a table that does not exist yet is correctly not an error;
- made the **forget windows a declared policy** (`forget-ladder-v2`, #87): episodes 30/90/180d, semantic 90/180/365d, and **preferences, procedures and identity never walk automatically** - a stale procedure is still the procedure, and losing it is the failure the ladder exists to prevent. `policy()` reports the effective table, each window has a `CORTEX_FORGET_<KIND>_DAYS` override that is validated and ignored when malformed, and the CLI prints which policy it used;
- added the **forget ladder** (`forget_ladder.py`, `scripts/forget_ladder.py`): deterministic cool -> archive -> tombstone, no model required. Kind sets the clock (episode 7/30/120d, semantic 120/240/540d, procedure 240/480/900d, identity 365/730/1825d), one rung per sweep, per-transition cap so a single run cannot mass-tombstone an import backlog, and protection re-checked every rung (pins, open commitments, core membership, any use evidence in 90d, corroborated edges). `tombstoned` means unreachable, not shredded - `restore()` walks it back up;
- made the profile a **read, not a search** (#121): `build()` 301ms -> 35ms on a live copy. Three fixes, each measured: the candidate pool was `ORDER BY importance` over every active memory (now `LIMIT 200`), the recent query was unbounded (`LIMIT 50`), and section classification ran the seven-regex chain over every candidate row (now shortlisted to 8 per section, cheap kind lookup first). The profile is also rendered **before** retrieval starts, so a slow turn or an empty recall can no longer drop the always-on block;
- added **core memory backup and restore** (`core_backup.py`, `scripts/core_backup.py`): export writes a human-readable Markdown profile (grouped entries with ids, source and verification dates) plus a JSON block, and restore rebuilds the profile **matching memories by content** so a backup taken from one database restores into another. Restore is a dry run unless `--apply`; a truncated export says so explicitly rather than silently dropping entries;
- added a **core contradiction check** (`contradiction.py`): promotion refuses a memory that would put two contradictory lines in the always-on block, detected either structurally (same `subject` + `predicate`, different `object_value`) or by polarity (same wording, negation on exactly one side). The write is blocked rather than one line hidden at render time - hiding would mean the block changing its mind by sort order. `cortex_memory core` reports any conflicts already present; `core_edit` surfaces a refused membership instead of reporting success;
- split core memory into a **stable profile plus a 24h recent appendage** (#129): the durable sections are capped at 75% of the budget and the warm `Recent (last 24h)` section takes the rest, so the part that is a promise cannot churn and the part that legitimately changes hourly cannot crowd it out. Memories touched inside the window are excluded from the general importance fill - otherwise the fill swallows them first and the recent section renders empty; `build(now=...)` pins the window for tests;
- added **model voice for core memory** (`core_voice.py`, `CORTEX_CORE_VOICE=1`): entries are rendered as directives with the exceptions lifted out (`Prefer X. Except: Y.`) and provenance scaffolding removed (`Vault note:`, `Path: …`, `Section: …`), saving ~19% of characters on the live pinned set so more facts fit the same budget. Rule-based and deterministic on purpose - the block must render without a model - and it never rewrites a memory it cannot parse cleanly;
- **core memory now renders in fixed sections** (`commitments`, `identity`, `people`, `projects`, `preferences`, `constraints`, `general`) with per-section character budgets, so one topic cannot crowd out another: unused capacity passes to sections that still have content, but nobody's guaranteed slot is spent on a single topic. Placement prefers the memory's own `kind` (mapped explicitly from the store's singular vocabulary), then `scope.active_project`, then a keyword fallback. The `core` action returns the block grouped by section;
- added **core memory read and edit from chat** (`cortex_memory` actions `core` and `core_edit`): `core` returns what the always-on block contains (chars, tokens, entries with their verified dates) and `core_edit` rewrites a fact through `correct_memory` - versioned, then membership re-asserted - so the block can be maintained from a phone instead of the dashboard. Short prefixes are accepted, secret-bearing edits are refused rather than redacted;
- **every core memory line now states when it was last verified** (`[verified YYYY-MM-DD]` or `[unverified]`): the latest of the core membership's confirmation, the memory's last helpful use and its last use. Promotion is explicitly not a verification - a fact promoted by the use rule was verified when it was last *used*, not when the rule fired. The join to `core_members` is conditional so a fresh store still renders a block;
- added a **core memory diff view** (`core_diff.py`): content-addressed snapshots of the rendered always-on block, written only when its SHA-256 changes, plus a real line-level diff (added/removed lines and ids) between consecutive snapshots. Promotion and demotion record one; `scripts/core_diff.py` shows the latest change, `--history N` lists snapshots and `--record` takes one on demand. Bounded at 500 snapshots;
- added **demotion rules** (`promotion.demote_stale`): a core member leaves when its memory is archived/superseded (immediately), or when it has been quiet past the window (default 90 days, `CORTEX_CORE_WINDOW_DAYS`). Quiet is measured from the latest of `last_confirmed_at`, `promoted_at` and the memory's own `last_used_at`, so a fact that keeps informing answers is never demoted for want of a restatement; pins outrank the timer. Membership changes are recorded in an additive `core_history` table, and `scripts/core_demote.py` runs the pass dry-run by default. Verified on a copy of the live store: 200 promotions, and 186 of them (the unpinned ones) correctly go stale after 400 days;
- added **promotion rules** (`promotion.py`): pin, repeated use (>= 3) or repeated confirmation (>= 2) records a memory in an additive `core_members` table, and core memory (#120) prefers those members ahead of the importance fill. Pinning through `cortex_memory` promotes immediately and a restatement refreshes the membership's `last_confirmed_at`; `scripts/core_promote.py` runs the pass (dry-run by default). Demotion only removes membership - the memory itself is never touched. On the live store: 241 candidates (227 by use, 14 pinned);
- added **core memory** (`core_block.py`): an always-injected 1,200-2,000 character block of pinned facts, open commitments and the most load-bearing stable memories, rendered by plain SQL with no FTS, embeddings or ranking model - it is the memory of last resort, so it depends on nothing but the tables. Section budgets (pinned 50%, commitments 85%, remainder importance) and per-line caps, because the first live run let nine pinned notes take the whole block and rendered one of 52 open commitments. Off by default (`CORTEX_CORE_MEMORY=1`): it costs ~460 tokens on every turn, which is a product decision with a price, not an optimisation;
- **removed the time-based TTL from the recall precompute memo**, and stopped memoising `due_prospective_memories`: every cached entry is now a pure function of the store revision. "Which commitments are due" depends on the clock, so caching it made selection time-dependent - a slow machine could legitimately return different memories than a fast one, which is what broke the preloaded/uncached parity benchmark on CI;
- **cut recall p50 from 142ms to 125ms** (p95 202 -> 182ms, max 322 -> 229ms) on the frozen set, no quality change: `superseded_ids` (12ms/turn) and the graph stage's superseded/contradicts lookups now come from the revision-cached edge sets; `select` reports its nine passes individually instead of as one number; and a **statement-count gate** (`tests/test_query_budget.py`) fails a PR that adds a per-turn query, because that is how this regression arrived;
- added **capture-time confirmation** (`confirmation.py`): a `remember` call whose content restates an existing memory records a `confirmed` event on that memory instead of staging a near-duplicate. Restatement uses the same two rules as redundancy (near-verbatim, or restated with high containment); correction markers disqualify a restatement, because a correction must create a new memory and supersede the old one. Re-checking a stored memory excludes itself; capture uses two lexical lookups (sorted distinctive tokens plus the full text) because either alone ranks the near-copies out of reach;
- added an **A/B harness** (`ab_policy.py`, `scripts/ab_recall.py`): policies are option sets, sessions are assigned one deterministically by session id (sha256, stable across processes and turns), and offline runs score every case under *both* policies so the comparison is paired with a bootstrap CI. Judges are pluggable - `coverage` (deterministic, free: did the injected block carry any of the case's relevant facts) and `model` (answers from the block, then grades). Every policy switch is now in the recall cache key, and `usage_boost` / `negative_cues` have real switches;
- replaced **first-match task classification** with a scored classifier (`task_class.py`): every class scores its vocabulary, phrases outweigh single words, terms shared between classes are demoted, a single weak word cannot classify (`MIN_SCORE = 1.6`) and split evidence returns `general`. On the labelled set (`evalsets/task-class-v1.jsonl`, 53 synthetic cases, `scripts/task_class_eval.py`): first-match 62.3% -> scored 83.0%, and the remaining misses abstain instead of filing a wrong class. `tool_guidance(None)` now means any class, so a `general` turn keeps its tool warnings;
- added per-stage timing for the post-candidate block (`superseded_lookup`) and made the unit of the counter stages explicit (`usage_boosted_count`, `entity_boosted_count`, `entity_expanded_count` - they were always counts, not milliseconds, and reading them as milliseconds sent an optimisation after the wrong query);
- added **warm-path precompute** (`precompute.py`): a revision-keyed memo (5s TTL) for the query-independent inputs to recall - due prospective memories, scoring profile weights, superseded/contradicts edge sets and the schema-source set. Also batched entity expansion (one query instead of one per candidate). Measured: `prospective_merge` 16.9ms -> 7.4ms per turn; the individual queries it replaces were 7.6ms (schema sources), 1.2ms (contradicts), 0.5ms (supersedes), 0.3ms (prospective), 0.01ms (revision);
- extended the **recall cache key** (`retrieval.search_cached`): the key now carries the query class, the anchored entity set, and every switch that can change a result (entity anchoring, entity boost, rerank, density budget, latency budget, abstention threshold). A flip used to reuse an entry computed under different rules; anchor names are memoised per store revision so the key costs less than the work it avoids;
- added the **cross-session continuity block** (`continuity.py`): a new session's first turn carries three lines about the previous one - what it was working on, what memory it used, how many commitments are open - built once, capped at ~200 chars, labelled derived and fallible. Also emitted on the zero-result path, which is exactly where a bare follow-up lands;
- added **query rewriting from session context** (`rewrite.py`): an underspecified follow-up (<=2 content terms) gets the session's recurring terms appended for retrieval only - "what about that" after a Seerr turn returns the Seerr memory (236-char block) where a cold session returns nothing. The original query is what the run records. 14 tests;
- added **budget by task type** (`task_budget.py`): shell/filesystem/github 8 memories at 900 tokens, data_analysis 7/800, web_research 6/700, memory 5/600, calendar+email 4/420, general 6/620, applied before the learned budget layer so learning starts from a per-task prior. Live probe: filesystem 3 -> 4 memories (605 -> 896 tokens), data_analysis 3 -> 4 and 5 -> 6, general unchanged. Every task type previously got 612-680 tokens and selected ~3.2 memories, so the limit was the real constraint;
- added **confidence-weighted budgets** (`density.py`): preload-scale budgets (>=2000 tokens) are now filled by confidence instead of by count - keep the head within 85% of the best score, spend until the budget is exhausted, never pad with the tail. Measured on six probe queries: 56% fewer preload tokens (22,595 -> 9,952) with a higher mean score in every case. Pure density ordering (score/token) was measured and rejected: it tripled down on short low-scoring memories;
- added **entity-anchored recall** (`entity_anchor.py`): extracts entity names from the query against the 489 usable names the store holds, fills `RetrievalContext.entities`, expands through entity-attached memories as candidates and adds a 0.10 association bonus. Measured: expansion finds ~19 candidates per entity query but the frozen effect is one case in 240 (hit@6 0.6167 -> 0.6208 at 0.10) - kept because it closes a real hole and is not worse;
- added **two-stage rerank** (`rerank.py`): BM25 over the top 50 candidates' contents, blended additively, tunable via `CORTEX_RERANK_WEIGHT`. **Off by default** - measured sweep on the frozen set: weight 0.00 gives hit@6 0.6167 / MRR 0.4382, 0.05 gives 0.6250 / 0.4260, 0.20 gives 0.5875 / 0.3593, 0.50 gives 0.5667 / 0.3294. The signal trades precision for nothing; the mechanism ships so the sweep is repeatable;
- added **query-class routing** (`cognition.query_class`): a turn is named lookup / planning / recall / chit-chat and each class gets its own plan - lookup widens slightly and lowers the threshold, planning takes 4 memories at a 520-token budget and a higher threshold, chit-chat needs no durable recall. Planning is matched before lookup so "what should we do next" is not read as a value question. Frozen: hit@6 unchanged 0.6167, recall 0.2997 -> 0.2969 (7 of 240 cases are planning);
- added the **read-time validity penalty** (`validity.py`): a memory some other memory supersedes is demoted to 0.35x at read time in current mode (history stays reachable, never wins a tie), skipped in historical mode because there the old value is the answer. Live store has 84 superseded memories and 0 elapsed `valid_to` windows;
- added **recall replay** (`recall_replay.py`, `scripts/recall_replay.py`): every turn stores the exact injected block, its memory ids, its token estimate and a SHA-256, so any answer can be re-derived byte-for-byte and verified; retention is bounded by `prune(days=30)` rather than by hope. Verified end to end through the real provider (193-char block read back with matching hash);
- added a **hard latency ceiling** (`latency_budget.py`): `latency_budget_ms` (or `CORTEX_LATENCY_BUDGET_MS`) stops starting optional phases and keeps the picks already made, recording `budget_exhausted`/`semantic_skipped` in stage diagnostics. Off by default so recall stays deterministic. Measured cost of the L1 work: p50 113.4 -> 111.0ms, p95 149.7 -> 157.5ms, max 205.4 -> 229.8ms, all within budget;
- added the **namespace leakage guard** (`namespace.py`, `tests/test_namespace_leakage.py`): a memory tagged `namespace`/`domain` in scope or metadata is withheld from any turn that declares a different channel - enforced in retrieval selection (before slots and tokens are spent) and in the always-on floor (which initially leaked: it selected `content` without `scope_json`, and the new test caught it). 18 tests across classification, admissibility and both live paths;
- added **project auto-detection** (`project_detect.py`): infers `active_project` from an explicit mention, the working directory, open files or recent messages, with alias matching (`temple-ios` matches `Temple/...`) and a deliberate refusal on ties. Live finding: 0 of 3,829 memories carry `scope.active_project`, so candidates must come from config `projects` until capture records them (new item #217);
- added **session-scoped recall** (`session_scope.py`): an elliptical follow-up ("do that", "the other one", "same for CT116" - no topic words, or a bare pointer) now boosts memories this session already touched, freshest first, by at most 0.06. A short query that names its own topic ("cortex roadmap") is not elliptical and is unaffected;
- added the **shadow abstention ledger** (`abstention_ledger.py`, `scripts/abstention_ledger_report.py`): every live turn records its top score, the memory it would have withheld at the calibrated threshold, and whether the real policy abstained - so the threshold can be tuned from real traffic while the policy stays disabled. Precision read means "withheld memory was later `used`". 8 unit + 1 integration test;
- added **redundancy collapse planning** (`redundancy.py`, `scripts/redundancy_report.py`): clusters near-duplicate memories (near-verbatim anywhere, restatements only inside one source), picks a canonical copy by use then importance then age, and reports the savings. Live store: 3,829 scanned, 24 clusters, 34 retirable copies, ~3,464 tokens. Read-only by design - collapsing is destructive and awaits approval;
- added the **abstention mechanism** (`abstention.py`, `docs/ABSTENTION.md`) with the policy **off by default**: measured AUCs on the frozen set say nothing separates a good recall from a bad one (top score 0.562, coverage 0.480, metacognitive confidence 0.447 - below chance), so the only tolerable threshold trades 3 real hits for 10 silenced misses. Guards make a threshold unable to silence pinned, previously-used or corroborated evidence. Three calibration scripts ship as the harness for the day a real signal exists;
- added a **diversity constraint** (`diversity.py`): at most two memories per source (vault note path, section anchors folded), plus a hard Jaccard ceiling on near-identical prose; duplicates are dropped rather than kept to fill slots, so a turn gets a shorter but distinct block. Live: the Seerr query returns 2 notes instead of 4 sections of the same note. Frozen hit@6 0.6208 -> 0.6167 (the demoted copies were sometimes the labelled hit);
- added **recency-vs-stability blend** (`stability.py`): a small capped boost (max 0.02) from `confirmed_count + validated_count + helpful_count`, saturating at five supports, halved for a single support, decaying with a 180-day half-life. Measured live: only 82 of 3,829 active memories carry any corroboration, so the blend is honest but nearly inert until reinforcement is captured (new item #216);
- added **negative-cue suppression** (`negative_cues.py`): queries carrying an exclusion ("not the X", "other than X", "except X", "anything but X", "without X", "don't mention X") now demote matching memories to 0.2x instead of confidently returning them. Demotion only - a misparsed sentence can never make a memory unreachable. Whole-word matching, terms capped at 4. Live check: "seerr telegram notifications (not the seerr)" drops every Seerr note out of the top 3;
- added **score transparency** (`recall_explain.py` + `scripts/explain_recall.py`): the top five results' scores and components are written to an additive `recall_score_breakdown` table inside the caller's transaction, so a bad recall can be explained afterwards and a rolled-back turn leaves no residue. 6 tests, 138 recall/provider/preload tests pass;
- added **use-weighted ranking** (`usage_weight.py`): a log-scaled, capped boost (max 0.09) from `access_log.event='used'` count, applied before the sort. Retrieval counts are ignored. Frozen set moved hit@6 0.5167 -> 0.6250, MRR 0.2927 -> 0.4415 — treat with suspicion, see the PR note on label leakage;
- fixed two latent crashes: `RetrievalResult` is a frozen dataclass, so the authority cap and the usage boost now return replacements instead of mutating, and read-only queries no longer open a write transaction (`store_read.py`) which had been adding a second COMMIT;
- added the **always-on floor** (`floor_context.py`): when the planner decides a turn needs no retrieval, the turn now still receives up to three always-on facts (open commitments, then pinned, then highest-importance), ~240 tokens, rendered through the same injection containment. Kills the "it didn't check memory" failure on greeting-shaped turns; 9 tests including a provider-level wiring test where `prefetch("hi")` returns the pinned fact;
- added `scripts/encryption_readiness.py` and `docs/ENCRYPTION.md`: reports whether the SQLite build can encrypt, whether the key file is private enough, and whether the store is plaintext, so an encrypted migration cannot be attempted by wishful thinking. Live verdict: NOT READY (no SQLCipher on this host, no key file). 10 tests;
- added `scripts/model_swap_drill.py`: runs the frozen set under the current model config and under an alternate one and requires identical recall, proving the "any model + great memory" thesis rather than asserting it. Live: current vs `hy4-flash-free` both `hit@6 0.5167 / recall 0.2448 / MRR 0.2934`, exit 0; 6 tests;
- added **prompt-injection containment** (`security.contain_directives`): recalled memory content that reads as a directive ("ignore previous instructions", fake `system:` turns, chat-template tokens, tool exhortations) is quoted in place and counted, so a stored note cannot issue orders. Applied in both provider render paths; 10 tests, 76 security/provider tests pass;
- added **source authority** (`source_authority.py`): a memory's score is capped when a higher-authority memory occupies the same subject+predicate slot, so a vault document or agent inference can no longer silently outrank the user's own words. Applied before the final sort; it only ever lowers a competitor. Retrieval suite 124 passed, frozen-set metrics unchanged (hit@6 0.5167, MRR 0.2927 -> 0.2934);
- added opt-in **phase tracing** for the four hot paths (`cortex_trace.py`, `CORTEX_TRACE=1`): recall, write, prune and consolidate each append one JSONL line with `phase`, `duration_ms`, `counts` (`candidates`/`returned`/`written`), a run id and the write `session_id` — so a slow turn can name the phase that was slow instead of attributing it to "Cortex". Tracing is off by default and the off path does no work (flag cached at import; each call site pays one boolean test — no clock, no allocation, no file handle), pinned by `tests/test_cortex_trace.py`; trace records carry no query text or memory content. `scripts/cortex_trace_report.py` reads the file, prints nearest-rank p50/p95/max per phase and every run strictly over its budget (defaults recall 250 ms, write 500 ms, prune 5 s, consolidate 60 s, `--budget phase=ms` overrides; exit 1 on a breach). Docs in `docs/PERFORMANCE.md`; `install_local.sh` ships the new module;
- added `scripts/backup_restore_drill.py`, a **restore drill** for the documented backup story that had never been proven. It takes an online snapshot through sqlite3's backup API (never a file copy of a live database — a `cp` of a WAL-mode file can capture a half-written state), restores that snapshot into a scratch directory with the backup API again, and verifies the restore with per-table row counts, a SHA-256 over a deterministic `ORDER BY id LIMIT 200` sample of `memories` and `edges` (equal counts alone cannot catch a same-size, different-content copy), and `PRAGMA integrity_check` on the restore. It prints `table -> source count -> restored count -> match/mismatch` and exits 0 only when everything matches, 1 on a mismatch or corrupt copy, 2 on unreadable input; `--keep` retains the restored scratch copy. The source is opened `mode=ro`, and the row counts are read inside the same read transaction that produces the snapshot, because a live Cortex database keeps taking writes: counting from a fresh connection afterwards reported six phantom one-row mismatches on the first live run against the 840 MB production database (fixed by holding one read transaction across counts + backup). Verified against the live database: **95 tables, 1,073,671 rows, `integrity_check ok`, exit 0** in 86 s, with `sample edges` reading 200 rows — `edges` has no `id` column, so the sample orders by the table's declared primary key (`src_id, dst_id, relation`) instead of assuming one shape. `tests/test_backup_restore_drill.py` (8 tests) covers the passing round trip, a corrupted copy exiting 1, missing/non-SQLite input exiting 2, `--keep`, source immutability, and the digest's ability to separate equal row counts with different content;
- added `scripts/storage_forecast.py`, an operator view of storage growth: per-table row counts and bytes (from `dbstat` when the SQLite build has it — table pages plus that table's indexes — otherwise a page-count split from sampled row payloads, and the report names which method ran), rows added per day over the last 30 days for `memories`/`edges`/`access_log`/`episodes` from their `created_at` (a table younger than the window is averaged over its own lifetime so it is not diluted 30-fold), and the resulting 30/90/365-day size projection with the linear-growth assumption printed alongside. `--sweep-trigger-mb` exits 1 when the 90-day projection reaches the threshold, so a timer can trigger maintenance before the disk fills; `--json` emits the same report machine-readably. The database is opened `mode=ro`. Measured live (2026-11-21): 800.8 MB with 220 MB of it freelist, `memory_features` 141 MB, growth 0.4 MB/day, 90-day projection 833 MB; `tests/test_storage_forecast.py` (13 tests) pins the projection arithmetic and rate window against a synthetic database with a known 10 rows/day;
- fixed headless OpenCode-relay calls and scoped mechanics providers: `_post_chat` now sends the relay's required `x-opencode-session` affinity header for `opencode.ai` endpoints (the value only has to be opaque and stable, so headless callers use a constant — the earlier `MissingSessionID` failure was the absent header, not an unmintable session) and applies `CORTEX_OPENCODE_REASONING_EFFORT` to OpenCode payloads so reasoning cannot exhaust the completion budget (observed live: the weights audit via `deepseek-v4.1-flash` returned `finish=length` with empty content until `reasoning_effort: low`); `brain_mechanics_config` gains `CORTEX_BRAIN_MECHANICS_ENDPOINT` / `CORTEX_BRAIN_MECHANICS_API_KEY_ENV`, so the mechanics passes (consolidate/schemas/prune/reconsolidate/tune) can run on a different provider than the admission judge — verified live against OpenCode Go serving `deepseek-v4.1-flash`, which restores the mechanics passes that had been failing HTTP 400 since 2026-09-08; four new tests pin the header/effort behaviour by endpoint and the scoped overrides;
- added the **Jev decision engine** for the automatic judge: `cortex/jev.py` is a stdlib-only (urllib) TypeSafe System One bridge — versioned question sets, corpus-calibrated policy paths (`default_p1` 0.60/0.40, `semantic_strict` 0.65/0.35, `builtin_memory` deferred to review), feedback-boost arithmetic matching the chat engine, per-item isolation, retries with backoff, an append-only decision log with no raw content, and a per-use fail direction. `CORTEX_AUTO_JUDGE_ENGINE=jev` routes admission through it with the chat provider as per-chunk fallback (`CORTEX_AUTO_JUDGE_JEV_FALLBACK`, default on; a Jev failure with fallback off rotates the paid-for batch and fails closed). Validation on the September corpus (read-only): **96.3% binary agreement** with the recorded judge on the current-model slice at a 29% defer rate, p50 333 ms per judgment, ≈$0.03 per 662-decision pass, 20 s wall at 12-way concurrency;
- added Jev **link judgments**: pairwise `l{i}`/`r{i}` gate+relation questions replace the single-shot linker for (a) link suggestions attached to admitted candidates (`CORTEX_AUTO_JUDGE_JEV_LINKS`, default on when the jev engine is active) and (b) the orphan-link pass (`CORTEX_AUTO_JUDGE_LINK_ENGINE=jev`). Edge creation requires gate ≥ `CORTEX_JEV_LINK_THRESHOLD` (default 0.65) plus a non-`none` relation and is capped per item; the model cannot invent memory ids. Link-quality replay over 400 sampled pairs: at 0.65 the gate re-creates **91% of operator-created edges and 84% of auto-judge edges** with ~3% random-pair pressure.
