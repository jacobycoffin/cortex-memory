# One binary, a user unit, and a coexistence smoke test

> **Read first.** `design/RUST-SERVICE.md` sections **Workspace**, **Deployment**, and the argv block. The three libraries already exist. This task wires them and proves the process does not migrate the database.

## Why

Operators need one binary and a unit file that can sit beside `cortex-dashboard.service` without taking its port. A single smoke test is the regression net for the strangler: Rust reads, Python's file stays at its schema version, the proxy reports a down upstream honestly.

## What to build

Append the `crates/cortex` member to `rust/Cargo.toml`. That is the only edit allowed in that file. The new crate is a binary named `cortex-rs` that dispatches the argv in the spec to the public functions of `cortex-cli`, `cortex-http`, and `cortex-view`. Do not reimplement parsing differences. Do not copy SQL into this crate.

`scripts/cortex-serve.service.in` and `scripts/install_cortex_serve.sh` match the Deployment section. The installer does not stop, disable, or rewrite `cortex-dashboard.service`. Default port is `8090`. The env file it creates does not contain a password. Templates use `@@HERMES_HOME@@`, `@@BIN@@`, and `@@PORT@@` placeholders. Do not write a root-owned home path or a `/Users/` path into either file.

Smoke tests, in `rust/crates/cortex/`:

1. Build a temporary database, set `meta.schema_version` to `34`, run `cortex-rs --db … status --json`, assert exit 0, assert the row is still `34`, assert the set of table names is unchanged.
2. Bind `serve` on an ephemeral loopback port with an auth file generated by `dashboard_auth.py`. `GET /api/pulse` without a cookie is 401. `GET /api/auth/status` is 200.
3. With `CORTEX_PYTHON_UPSTREAM` pointed at a closed port, `GET /api/snapshot` is 503 and the body has a `note`.
4. `cortex-rs --db … pulse --once` against an empty `usage_records` exits 0 and prints a grid of empty glyphs (or the ASCII set under `--ascii`).

## Acceptance

- `cargo build --release -p cortex` produces `cortex-rs`.
- The four smoke checks above pass.
- `install_cortex_serve.sh` is safe to run with `UNIT_DIR` pointed at a temporary directory: it writes a unit and an env file and does not call `systemctl` when `CORTEX_SERVE_INSTALL_NO_SYSTEMCTL=1`. The unit text contains `127.0.0.1:8090` when `PORT` is unset, `ReadWritePaths` ends in `/cortex`, and it does not mention `cortex-dashboard.service`.
- `python3 scripts/check_repository.py` passes, which it will not if a database or an auth file was committed.

## Out of scope

Retiring the Python dashboard, porting `sleep.py`, changing crate-internal SQL, editing HTML.
